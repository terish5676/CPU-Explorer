# CPU Performance Explorer

A lab-instrument style tool for Computer Organization & Architecture: cache, pipeline and
memory-locality simulators, plus a live multi-language Code Lab and a transparent rule engine
that explains *why* two runs differ.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build
npm test
```

## Stations

| Route | What it does |
|---|---|
| `/` | Index with a live pipeline diagram generated by the real simulator |
| `/code-lab` | **Every language runs for real.** JavaScript in a sandboxed Web Worker; C / C++ / Python / Java via Judge0 CE. Edit freely, pass stdin, measure wall time, save runs |
| `/cache` | Set-associative cache (LRU/FIFO/Random). Play/scrub every access: tag·index·offset bits, live set grid, hit/miss strip, log |
| `/pipeline` | 5-stage pipeline, live as you edit. Cycle playhead, datapath view, hazard log, forwarding on/off delta |
| `/memory` | Trace generator + stride/spatial/temporal locality, scatter plot, one-click send to the cache simulator |
| `/assembly` | Instruction-mix classifier with category highlighting |
| `/monitor` | Chart any metric across saved runs |
| `/analysis` | Six printed rules (R1–R6) compare two runs; every finding is labelled Observed vs Simulated |
| `/runs` | Rename, delete, export/import JSON, load sample runs (generated by the real simulators) |
| `/about` | Methodology and honesty notes |

Paper / Phosphor themes are toggled in the header and remembered.

## Data honesty

Every figure is stamped **Measured**, **User trace** or **Simulated**.

- **Measured** — Code Lab wall time from a real runner (local Worker or Judge0 CE).
- **User trace** — Cache / memory results computed from addresses you supplied.
- **Simulated** — Deterministic teaching models (pipeline, synthetic generators). Same input → same output; not hardware PMCs.

Cache and pipeline are intentional COA teaching instruments: every control drives the live model.
